# site-assistant

Stages 1–5 use a modular Go monolith and React/Vite clients. Existing root GoLand sample is not the application; work in `backend/`, `frontend/`, `widget/`. No push or production actions without explicit authorization.

- HTTP adapters: `backend/internal/httpapi`. Foundation business rules: `internal/core/service.go`, `auth.go`. Knowledge rules/worker: `internal/knowledge`. AI engine: `internal/ai`. SQL only in repository methods (`core/store.go`, `knowledge/store.go`, `knowledge/extracted.go`, `ai/store.go`) and migrations. Keep the module small.
- Every tenant operation must call `Service.Access`; every entity lookup/update/delete includes organization ID. Client IDs never prove membership. Composite sites/assistants FK is required.
- Owner controls company settings. Owner/admin write assistants/sites and invite admin/operator. Operator writes only own website inbox conversations, may take unassigned open ones; cannot access preview or change KB/system settings. Invitation acceptance never changes an existing role. See docs/operator-inbox.md.
- Passwords Argon2id; server sessions stored as SHA-256 digests. Never put secrets/PII into logs or auth tokens into browser storage. Mutations require exact Origin + custom CSRF header + JSON.
- RU/EU have separate infrastructure and databases. Language is independent. All UI strings in four complete dictionaries; API returns stable machine error codes.
- Stage 2 includes knowledge/files/import/retrieval. Stage 3 adds AI/preview. Stage 4 adds public iframe website chat using the same AI engine, explicit mock/disabled/Ollama modes. No real Gemma/GPU connection/download, leads/billing/CRM. `active` remains forbidden; widget enabled is a separate channel flag. Keep real BGE-M3 checks separate from mock generation and Ollama contract tests.
- Knowledge: composite organization/assistant/source FKs; authorize every route with Knowledge.Access. Atomic active_revision publication only after validated embeddings for the whole revision. Compare model digest/dimensions; never mix models. Lease tokens fence stale workers, timeouts must remain shorter than the 5-minute lease.
- All importer requests use pinned public DNS IPs, no proxy, bounded redirects/body/time, and robots.txt checks. Never bypass SSRF checks for a development test URL. Test transport mocks do not weaken the production transport.
- Files use random keys under KNOWLEDGE_FILE_ROOT; never serve originals publicly. PDF uses a resource-limited, nonnetworked Poppler CLI container. Build with `docker compose build extractor`; never remove PostgreSQL volumes. See docs/rag.md.
- Append SQL migrations; never rewrite migrations already deployed. Do not truncate databases. Integration tests require `TEST_DATABASE_URL` with database name ending `_test` and use isolated schemas.
- Before handoff: in backend `go test ./...`, integration tests with test DSN, `go vet ./...`, `go build ./cmd/api`; in frontend `npm ci`, `npm test`, `npm run build`, `npm audit`. Browser tests: `npx playwright test` with local servers pointed at a test database. Regenerate OpenAPI after API changes with `node scripts/generate-openapi.mjs`.
- Do not commit `.env`, IDE settings, binaries, screenshots or node_modules. Preserve unrelated changes.
- AI rules: `internal/ai`, SQL in ai/store.go; reuse knowledge.Search. Composite tenant FKs, DB idempotency and one active execution per conversation. Never persist partial output or thinking. Budget prompts and treat RAG as untrusted data. No-knowledge Ollama path uses server fallback. No tools/actions. Mock forbidden in APP_ENV=production. See docs/ai-engine.md; do not contact the old GPU server. AI_BASE_URL and OLLAMA_BASE_URL are independent regional settings.
- Full RAG checks (backend): TEST_DATABASE_URL ending `_test`, PDF_TESTS=1, PUBLIC_IMPORT_TESTS=1, REAL_EMBEDDINGS=1, optional RAG_REPORT_PATH absolute path; `go test ./... -count=1 -v`. Actual Recall@5 corpus is testdata/multilingual.json; never replace real results with mocks. Browser knowledge scenario also uses real Ollama and a test DB. Repeat full browser suites with a fresh local API process or wait for the login rate limit.
- Widget: `internal/widget` service/repository and `httpapi/widget.go`; website authorization also checked by AI.WebsiteScope before common generate. Never create a second inference/retrieval engine. Public widget ID is not secret; opaque visitor tokens are stored hashed in DB and may be stored only in parent sessionStorage (explicit exception to cabinet token rule). Never URL/localStorage/logs. Exact origin allowlist, CSP frame-ancestors, postMessage source+origin+channel; no wildcard CORS or third-party cookie dependency. Production requires ownership verification and forbids localhost bypass/mock. Keep PG budgets atomic; memory fast limiter is single-process. See docs/widget.md.
- Build/test widget: `npm ci`, `npm test`, `npm run build`, `npm audit` in widget/. Build before browser tests so Go serves current widget/dist; dev4173 serves independent HTML demo, iframe/assets/API come from Go8080. Browser API: existing *_test DB, AI_PROVIDER=mock, WIDGET_ALLOW_LOCALHOST=true. Artifacts in ignored artifacts/stage4, artifacts/stage5 and frontend/test-results; no screenshots in commits.
- Inbox: internal/inbox service/store, SQL in store.go and invitations.go. Website only. All mode changes, manual replies, AI begin and successful Finish take the same conversation row FOR UPDATE. Website Deliver holds FOR SHARE THROUGH bounded SSE flush and checks mode/execution version. Never replace this with a pre-write check or memory flag: a handoff must exclude every subsequent stale send/finish across processes. Cancel and Recover follow conversation-before-execution lock order. See docs/operator-inbox.md.
- Messages keep original sequence order and change_seq for incremental updates; status updates and mode/note events use conversation_change_seq. Cursor readers lock conversation FOR SHARE. Public DTO excludes notes, actors, assignment metadata and tenant/internal AI IDs. Notes never enter AI history; completed operator replies map to assistant history, canceled AI replies are excluded.
- Browser regression: old 5 scenarios (`npx playwright test knowledge.spec.ts preview.spec.ts widget.spec.ts workspace.spec.ts`) and, after restarting your own local test API to reset auth limiter, `npx playwright test inbox.spec.ts`. Inbox registers 3 users; do not weaken login limits for one combined suite. Real process restart: build backend then TEST_DATABASE_URL *_test `node ../scripts/test-inbox-restart.mjs` from backend; script stops only its own child on port18085. No Stage 6 without request.
