# Business analytics — Stage 9A.3

Analytics is a read-only company view for Owner/Admin. Operators retain their existing assigned/unassigned inbox and lead permissions and cannot read company-wide aggregates. Preview conversations never enter this report. There is no new model call, tracker, event stream, cache, queue or customer-message copy.

## Source matrix and definitions

Every SQL scope includes organization_id. A single PostgreSQL statement gives an MVCC-consistent report. Let P=[start,end) be inclusive selected calendar dates converted to UTC boundaries in the chosen IANA timezone. Q is the immediately preceding equal number of local calendar days, so DST days may have 23/25 hours. Range: 1–93 days. Cohort C is website conversations created in P. History checks stop at end, not at query time.

| Metric | Source / SQL formula | Available | Precision / exclusions |
|---|---|---|---|
| Conversations | count(C) | Yes | Includes empty sessions' conversations; not unique people, visits or site traffic. Deleted conversations disappear. |
| Website requests | count(leads where source IN ('website','staff') and conversation_id IS NOT NULL and created_at in P) | Yes | Surviving visitor- or staff-confirmed public-chat leads; may belong to conversations started earlier. Source/status breakdown separates staff/website/API. External API leads excluded. |
| Eligible conversations | count(C with EXISTS visitor message created_at<end) | Yes | A cohort denominator, not all website visitors. |
| Request conversion | count(eligible C with submitted lead_collection.submitted_at<end) / eligible C | Yes | Unique conversation, including explicitly staff-confirmed collections. Submitted tombstones retain confirmation after lead deletion. Not a same-period lead-count/dialogue-count ratio. External standalone API leads never enter numerator. Zero denominator = null. |
| Without operator | count(C without completed operator message or human_active event before end) / count(C) | Yes | Human request alone is not manual participation. No claim that AI resolved anything. |
| Human handoffs | count(distinct conversation_id with human_requested or human_active event in P) | Yes | Includes direct takeover; repeated transfers count once per period. Daily series counts once per day and need not sum to period distinct count. |
| AI generation time | avg(provider_duration_ns)/1e6, completed Ollama with known positive provider duration, execution created in P | Yes, sparse | Not time to first token, end-to-end request latency or Mock duration. Null if unknown. |
| Execution statuses | count by provider/status, execution created in P | Yes | Current stored status of requests started in P, not a reconstructed status at period end. Completed is a programmatic outcome, not successful consultation. Mock separately labelled; never commercially counted. |
| Tokens | sum(input_tokens), sum(output_tokens), by provider/status in P | Partial | NULL when none known; sums include only reported values, not estimates. |
| Context without sources | distinct conversation with policy_fallback=true and settings_snapshot<>'{}', execution in P | Yes | Existing policy_fallback means prompt context had no selected sources. It does NOT prove an actual server fallback was delivered. Old/unprepared executions have no reliable retrieval signal. Not an NLP diagnosis of a knowledge gap. |
| Execution failure | status='failed', execution in P | Yes | Technical category, separate from lack of sources; no guessed cause or transcript exposure. |
| Attention list | failed execution OR prepared empty-source context | Yes | Paginated execution records with site/assistant/category/date/conversation link; no contents/contacts. A conversation may have multiple incidents. |
| Handling distribution | cohort split by any manual participation before end | Yes | Two mutually exclusive buckets. Current waiting/human-active counts are a separate current-state snapshot and must not be added to the historical distribution. |
| Accepted conversations | distinct conversation with human_active event actor=member in P | Yes | Actual actor, not last assignee; repeated takeovers by that actor count once. |
| Manual replies | completed operator messages with author_user_id=member, sent in P | Yes | Reassignment does not move authorship. Notes excluded. |
| Closed conversations | distinct conversation with closed event actor=member in P | Yes | Actual closing actor; not inferred from current assignment. |
| First human response | mean(first completed operator message time − handoff episode start) | Yes for retained history | Episode starts human_requested/direct human_active after AI/closed mode. Ends at next ai_active/closed, bounded by common change_seq to preserve concurrent ordering. Episode start must be in P; first response before end. Attribution to actual replying author. Unanswered episodes and inconsistent negative timestamp samples excluded; sample count shown, not an SLA. |
| Assigned now | current nonclosed website conversations assigned to member | Yes | Current snapshot, independent of historical date filter; site/assistant filters apply. |
| Lead sources/statuses | count by source and current status for leads created in P | Yes | API/staff/website separate. Status is current, not reconstructed as of period end. |
| Sites/assistants | same cohort/activity measures grouped by conversation.site_id and conversation.assistant_id | Yes | Historical stored IDs, current display names. Current widget reassignment does not reattribute old conversations. Lead-only/handoff-only activity retained even with zero new dialogs. Sort + 20-row pages. |
| Plan usage | existing billing Snapshot | Yes | Current billing period, not historical analytics interval. Used/reserved/remaining from original atomic ledger. No new monetary estimates or quota changes. |
| API request volume | existing integration counters are protective windows, not a historical request journal | No | Not offered as historical API analytics. |
| Resolution / answer correctness / reason for human request / visitor satisfaction | no reliable structured outcome | No | Not inferred from completed executions, no-human mode or message text. Future explicit signals/evaluation needed. |

KPI comparison uses the same formula in Q, evaluated at Q.end. Relative percentage change is `(P−Q)/abs(Q)*100`; missing values or Q=0 produce no percentage, not infinity or invented growth. Conversion and no-human shares remain defined ratios, not counts. No-data generation stays null; zero activity counts remain 0.

## API and safety

`GET /api/v1/organizations/{id}/analytics` returns period/current+previous KPI, zero-filled daily timeseries, handling, execution/provider counts, lead sources/statuses, paginated site/assistant breakdown, global insights, attention and operator aggregates.

Query: `from=YYYY-MM-DD&to=YYYY-MM-DD&timezone=Europe/Prague&site=UUID&assistant=UUID&page=0&sort=dialogs|leads|handoffs|conversion`. Dates inclusive in UI, exclusive end in UTC SQL. Invalid dates, timezone, UUID, page or range return validation. Page size20, max page1000. Missing dates default7 calendar days. Unknown/foreign filter IDs return empty intersections and cannot grant access. Authentication and Service.Access precede data reads; owner/admin required, nonmember404/operator403. No public analytics endpoint. An 8-second context bounds report work. No FOR UPDATE/SHARE locks or transactions across UI/inference.

Migration `011_analytics_indexes.sql` adds seven period/first-message indexes to existing conversations/executions/events/messages. No tables/fields/event retrofill; migrations001–010 untouched. Source metadata and lead counters are not altered. SQL is in analytics/store.go, authorization/validation in service.go, HTTP adapter in httpapi/analytics.go. Execution, event and lead CTEs project only needed metadata and do not copy contact values, settings or RAG text into materialized results.

Measured query-plan defects were fixed: indexed first-visitor/operator/takeover timestamps replace repeated semi-joins; site/assistant event attribution is prepared once. A short read-only transaction sets LOCAL jit=off and enable_nestloop=off for this report only: fresh-import cardinality estimates otherwise produced quadratic joins and JIT overhead. Settings restore at transaction end; required indexed LATERAL joins remain possible. No server-wide planner configuration change. EXPLAIN in the test uses the same local settings. Report work is bounded by an 8-second context, cleanup by one second.

## Product and design

Company → Analytics has Overview, AI quality, Team; all text is in four analytics.json dictionaries registered with existing i18next. Date/site/assistant selections persist as an_ query parameters. Explicit calendar timezone controls period boundaries. Real quota summary is separate from the date filter and links to Plan & usage. Attention links use existing inbox authorization. Leads link to existing CRM; no duplicate lead editor or unsupported source filter is invented.

Shared font/palette tokens were extracted without changing values from marketing/cosmic.css into design/cosmic-tokens.css, scoped to .cosmic/.analytics. Analytics styles are scoped, predominantly light, with a violet insight panel, large readable KPI, charts, contextual definitions and responsive tables. Other cabinet/widget styles and marketing layouts are unchanged.

Charts are lightweight SVG/React, no extra chart dependency: integer axis, zero-filled calendar days, series switches, point titles/pointer selection plus keyboard-accessible date selector showing exact values. ResizeObserver adapts plot coordinates and tick density to available width instead of shrinking the text or hiding recent dates. Tables scroll inside focusable labelled regions. Reduced motion supported. Insights use only actual aggregate comparisons, globally ranked public-chat leads/assistant handoffs and execution failures, without LLM/NLP or fabricated advice. A failed filter request clears the old snapshot rather than presenting stale figures under a new period; displayed dates come from the returned snapshot.

Limitations: deleted conversations/leads affect surviving-record counts; conversion retains submitted collection tombstones. Human motivation, satisfaction, resolution, first visible AI token and actual consultation quality cannot be derived reliably. Provider durations/tokens may be absent. Current-state snapshots and billing periods are explicitly distinct from historical cohorts. No saved historical API-volume journal, LLM classification, cash-cost estimate, shared analytics cache or long endurance/GPU benchmark is provided. Chromium checks do not replace a Safari/Firefox/device matrix. Real Gemma evaluation remains Stage9B; no GPU, S3 live writes, external CRM or production deployment was performed.
