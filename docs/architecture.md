# Архитектура

Модульный монолит Go с REST `/api/v1` и PostgreSQL/pgx. `cmd/api` управляет конфигурацией, пулом, миграциями и lifecycle. `internal/httpapi` декодирует запросы, проверяет сессию/CSRF, ограничивает парольные операции и сериализует ошибки. `internal/core` содержит доменные модели, service с валидацией/правами и отдельный SQL repository. Это намеренно компактная версия предложенной структуры: шесть малых пакетов по сущности пока создали бы лишние переходы и зависимости.

Поток: HTTP → Service → Store → PostgreSQL. Чтение профиля/списка доступных компаний и проверка сессии не требуют дополнительных бизнес-правил; адаптер вызывает repository напрямую. Изменения tenant-сущностей проходят Service.Access. Запросы сущностей всегда имеют tenant-предикат; отсутствие членства возвращает 404, недостаточная роль — 403. Политика ролей не зависит от клиента. Приглашений и API изменения участников нет.

Frontend: React + TypeScript + Vite, i18next, fetch с HttpOnly cookies. Страницы входа/регистрации, компании/обзор, ассистенты, сайты, настройки и профиль. Нет фиктивных разделов. Ошибки, загрузка, пустые состояния, подтверждение удаления сайта. Даты используют часовой пояс компании и язык пользователя; счётчики — Intl.NumberFormat. UI получает бренд/регион из публичного `/config`.

Пароли: Argon2id 64 MiB, 3 итерации, 2 потока, соль 16 байт, ключ 32 байта. Сессии: 32 случайных байта, в БД SHA-256, абсолютный срок 7 дней. Logout отзывает текущую сессию. Истёкшие записи очищаются раз в час. Dummy-хеш делает проверку неизвестной почты сопоставимой по стоимости. Регистрация существующего адреса не меняет пароль и возвращает тот же 202, без сессии. Ни почта, ни токены не логируются.

CSRF: точное совпадение Origin с PUBLIC_APP_URL, `X-CSRF-Protection: 1`, JSON Content-Type для всех мутаций, включая login/logout/register. SameSite=Lax, HttpOnly; Secure в production. CORS не включён, frontend и API публикуются под одним origin. Парольные операции ограничены 4 одновременными вычислениями на процесс и 10 попытками с peer IP за 15 минут. X-Forwarded-For не считается доверенным. За reverse proxy необходим дополнительный edge rate limit (см. deployment).

Расширение: знания, inference и widget будут отдельными модулями в этом процессе. Они получат organization_id и тот же механизм прав. Пользователь имеет независимый UUID: будущие OIDC identities будут отдельной таблицей с `(issuer, subject)`, связанной с users; перед добавлением OIDC password_hash станет nullable миграцией. Не связывать пользователей автоматически по неподтверждённой почте.

Ограничения: нет пагинации, истории аудита, приглашений, ревокации всех сессий, email verification и recovery. Модальные окна удерживают фокус и закрываются по Escape; перед production нужен отдельный accessibility review. Graceful shutdown: 10 секунд, HTTP timeouts, закрытие pgx pool. Логи JSON с операционными событиями без содержимого запросов.
